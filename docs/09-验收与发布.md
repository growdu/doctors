# 09 · 验收与发布

> 本章定义 v1.0 的验收标准、上线 Checklist、版本管理规范。  
> 所有功能 / Bug 必须在达到验收标准后方可上线。

---

## 9.1 验收原则

1. **业务闭环优先**：先打通端到端主流程，再优化细节。
2. **真实环境验证**：核心场景必须在 staging 用真实三方（微信支付沙箱、实名 mock、真实短信）。
3. **可演示**：每个 P0 功能必须有"演示脚本"，PM 能完整跑通。
4. **数据可观测**：上线后核心指标必须有 Dashboard，异常可秒级告警。

---

## 9.2 P0 验收 Checklist

> 以下全部为**必须通过**项。

### 9.2.1 患者端

- [ ] 注册 / 登录（手机号 + 微信）三端均通过
- [ ] 实名认证（mock 实名服务商）三端均通过
- [ ] 浏览医院 / 服务包（含筛选 / 搜索）
- [ ] 下单 → 微信支付（沙箱） → 支付成功
- [ ] 订单进入匹配池后陪诊师可接单
- [ ] 订单详情展示陪诊师虚拟号
- [ ] 服务完成 → 评价 → 双向评价展示
- [ ] 申请退款 → 自动原路退回（沙箱）
- [ ] 个人中心、优惠券、地址管理可用
- [ ] SOS 一键报警触发紧急联系人推送

### 9.2.2 陪诊师端

- [ ] 注册 → 实名 → 上传健康证 → 培训考核 → 协议签署
- [ ] 提交审核 → 管理员审核 → 通过
- [ ] 上线后进入抢单池 / 可被派单
- [ ] 接单 → 到院签到（GPS 校验）→ 打卡 → 结束服务
- [ ] 钱包可见收入 / T+7 冻结 / 提现申请
- [ ] 培训课程学习 / 考核通过有记录

### 9.2.3 管理后台

- [ ] 仪表盘显示真实指标
- [ ] 医院 / 服务包 / 优惠券 CRUD
- [ ] 陪诊师审核工作流
- [ ] 订单监控 + 改派 / 退款
- [ ] 财务对账 + 提现审核
- [ ] 工单 + 客服首响 SLA 监控

## 9.3 非功能验收

- [ ] 性能：核心接口 P95 / P99 达标（见 05）
- [ ] 稳定性：压测下单 QPS ≥ 500，持续 30 分钟无错误率上升
- [ ] 安全：通过渗透测试报告（含 OWASP Top 10 复查）
- [ ] 合规：医疗合规自查通过（陪诊 ≠ 诊疗话术、隐私政策、用户协议）
- [ ] 可用性：核心服务 ≥ 99.9%
- [ ] 可观测：所有关键接口埋点 + TraceID + 告警

## 9.5 发布流程

### 9.5.1 环境

| 环境 | 用途 | 数据 |
| :-- | :-- | :-- |
| dev | 开发自测 | 假数据 |
| staging | 联调 / 验收 | 脱敏后的真实数据 |
| prod | 生产 | 真实数据 |

### 9.5.2 发布节奏

- **每周二 / 四**为常规发布窗口
- **大版本**（含数据迁移）单独排期 + 灰度
- **热修**走紧急通道，需审批 + 灰度

### 9.5.3 灰度策略

| 维度 | 灰度比例 |
| :-- | :-- |
| 城市 | 1 → 5 → 20 → 50 → 100% |
| 用户标签 | 内部员工 → 小流量 → 全量 |
| App 版本 | 最低版本以上逐步放量 |

灰度期间监控核心指标：成功率、错误率、投诉率；任一阈值越线立即回滚。

### 9.5.4 回滚

- 应用层：一键回滚到上一个稳定镜像
- 数据库：向前兼容的变更可平滑回滚；破坏性变更必须有前置备份
- 配置：通过配置中心秒级回滚
- 三方：保留旧通道开关，必要时切换

## 9.7 版本管理

- **API 版本**：`/api/v1`、`/api/v2`，旧版本至少保留 6 个月兼容期
- **App 版本**：语义化版本 `MAJOR.MINOR.PATCH`
  - MAJOR：架构 / 协议级变更
  - MINOR：新增功能
  - PATCH：Bug 修复
- **小程序版本**：每次发布必须能在微信后台回滚
- **后端版本**：Git tag + 镜像 tag 同步

---

## 9.8 沟通与变更管理

- 所有需求变更必须走变更评审（产品 + 研发 + 测试 + 运营）
- 紧急变更可口头同步，**24h 内补单**
- 重大变更（涉及合规、资金、隐私）必须有法务 / 合规会签
