# 05 · 非功能需求

> 本章定义性能、安全、合规、可用性、可维护性等"看不见但很关键"的底线要求。  
> 所有功能开发、测试、运维都应以此为准。

---

## 5.1 性能

### 5.1.1 响应时间

| 接口类型 | 目标 P95 | 目标 P99 |
| :-- | :-- | :-- |
| 登录 / 注册 | < 800ms | < 1.5s |
| 首页 / 列表 | < 1s | < 2s |
| 下单 / 支付 | < 1.5s | < 3s |
| 抢单推送 | < 500ms（推送延迟） | < 1s |
| 后台查询 | < 2s | < 4s |
| 后台报表 | < 5s | < 10s |

### 5.1.2 容量

- 注册用户：≥ 100 万
- DAU：≥ 5 万
- 峰值订单/日：≥ 5000
- 峰值 QPS（接口）：≥ 500
- 图片 / 文件存储：≥ 1TB

### 5.1.3 可扩展性

- **水平扩展**：Go 服务无状态，单二进制 < 30MB，K8s / SLB 弹性扩缩容（冷启动 < 500ms）
- **数据库**：v1.0 单库单实例 + 读写分离 + PostgreSQL 原生分区表（评价按 `created_at` 月分区、订单按 `user_id` HASH 分区预留）；v2.0 引入分库（`pgcat` / `Citus`）
- **缓存**：Redis 7 集群
- **异步化**：订单事件 / 通知 / 结算走 Kafka（Go 客户端成熟）
- **PG 扩展能力**：JSONB 灵活字段、`LISTEN/NOTIFY` 替代部分 Pub/Sub、`tsvector` 全文检索降级 ES 依赖

## 5.2 可用性

| 指标 | 目标 |
| :-- | :-- |
| 服务可用性 | ≥ 99.9%（年宕机时间 < 8.76h） |
| 核心链路可用性 | ≥ 99.95% |
| 数据持久性 | ≥ 99.999% |
| RTO（恢复时间目标） | < 30 分钟 |
| RPO（恢复点目标） | < 5 分钟 |

- 多 AZ 部署
- 关键服务至少 2 个实例
- 数据库：Patroni + etcd 主从仲裁 + 同步复制（RPO=0）；每日 `pg_basebackup` + WAL archive 增量备份
- 灰度发布 / 蓝绿部署

## 5.3 安全

### 5.3.1 账号安全

- 密码：BCrypt + Salt；最少 8 位、含字母数字
- 短信验证码：60s 有效，错误 5 次锁定
- 异地 / 新设备登录：触发二次验证
- 连续登录失败：账户锁定 30 分钟

### 5.3.2 数据安全

- 敏感信息加密存储（AES-256）
- 身份证号、人脸图：仅存哈希 + 末四位
- HTTPS 全链路（TLS 1.2+）
- 数据库审计日志开启
- 关键操作二次确认

### 5.3.3 接口安全

- 所有接口走统一鉴权（JWT + refresh token）
- 防重放：timestamp + nonce
- 防爬：限流（IP / 用户 / 接口三级）
- 防 SQL 注入：ORM 参数化
- 防 XSS：输入过滤 + 输出编码
- 防 CSRF：移动端忽略，小程序靠 referer / token

### 5.3.4 资金安全

- 用户资金与平台账户严格隔离
- 任何退款 / 提现操作必须有审计日志
- 大额（≥ 1000 元）操作触发风控 + 人工复核
- 财务相关接口单独 VPC、白名单访问

### 5.3.5 隐私合规

- 收集个人信息遵循"最小必要"原则
- 用户协议 + 隐私政策需用户**主动勾选**
- 提供"个人信息导出"与"删除"功能
- 用户注销 30 天后 PII 物理删除
- 内部访问 PII 需申请 + 审批 + 审计

## 5.4 合规

### 5.4.1 医疗合规红线

> ⚠️ 本平台**不涉及任何诊疗行为**，必须严格区分"陪诊"与"诊疗"。

| 禁止行为 | 替代说法 |
| :-- | :-- |
| 给出医学诊断 | "我不是医生，无法判断" |
| 推荐用药 | "请遵医嘱" |
| 解读检查报告 | "请咨询主治医生" |
| 代替医生做决定 | 仅做流程引导 |

- App / 小程序首页、订单详情、陪诊师端均需展示"陪诊 ≠ 诊疗"提示
- 陪诊师培训必修内容包含合规话术
- 用户协议明确告知"陪诊师非医务人员"

### 5.4.2 资质合规

- 陪诊师**必须**持有效健康证上岗
- 平台留存健康证复印件 + 编号 + 有效期
- 到期前 30 天提醒复审
- 涉及宣传"医护背景"的，需配套展示相关证件（脱敏）

### 5.4.3 支付合规

- 使用持牌第三方支付（微信支付）
- 资金清结算走合规通道，不做资金池
- 发票合规：支持电子普通发票、增值税专票

### 5.4.4 数据合规

- 个人信息保护法（PIPL）合规
- 数据不出境
- 跨境数据传输需用户单独同意（如使用境外云）

## 5.5 可维护性

### 5.5.1 代码

- 模块化、服务化（微服务 / 中台化）
- 单元测试覆盖率 ≥ 70%
- 关键路径（支付、下单）覆盖率 ≥ 90%
- 静态扫描通过、依赖漏洞扫描通过

### 5.5.2 监控告警

- **基础监控**：CPU / 内存 / 磁盘 / 网络
- **应用监控**：QPS / RT / 错误率 / 慢调用
- **业务监控**：订单转化率、支付成功率、抢单响应率
- **日志**：全链路 TraceID（OpenTelemetry / SkyWalking）
- **告警**：分级（致命 / 严重 / 警告），对接企业 IM / 短信

### 5.5.3 文档

- API 文档（OpenAPI 3.0）
- 接口变更日志
- 数据库字典
- 部署手册 + 运维 Runbook

---

## 5.6 可测试性

- 区分环境：dev / staging / prod
- 测试金字塔：单元 / 接口 / UI / E2E
- 关键 E2E 用例：注册 → 下单 → 支付 → 接单 → 服务 → 评价 → 退款
- Mock 服务：微信支付、实名、短信、Push
- 性能压测：定期演练

---

## 5.7 国际化与本地化（v1 不强制）

- 多语言：先支持中文简体，预留扩展能力（i18n key）
- 多时区：默认 GMT+8（北京时间），所有时间字段带时区
- 多币种：先支持 CNY，预留多币种扩展

---

## 5.8 易用性

- 主要按钮 ≤ 3 步可达
- 关键文案字号 ≥ 14pt（针对老年用户）
- 老人模式：可选大字号、语音输入
- 错误提示必须有"下一步怎么办"，不能只说"失败"
- 关键流程（实名、支付）必须配示意图或视频教程

## 5.10 应急与灾备

| 场景 | 预案 |
| :-- | :-- |
| 数据库主库宕 | Patroni 仲裁自动提升，RTO < 10s |
| 机房整体不可用 | 多 AZ + 异地灾备，RTO < 30min |
| 微信支付通道异常 | 切换备通道；引导用户稍后重试 |
| 大规模投诉 | 启动应急小组；统一对外口径 |
| 陪诊师大规模缺席 | 启动储备池；优先保障已支付订单改派 |
| 安全事件 | 启动安全响应小组，48h 内对外披露（如需） |
